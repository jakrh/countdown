## What's new

**Setting the time can no longer go wrong.** A digit that doesn't fit, such as 7 in the tens of seconds, is refused as it is typed, so `Enter` always works, where a bad entry used to fail silently. The four digits are typed over in place, a blinking cursor moves with `←` `→`, and `Backspace` sets the digit under it back to 0. A second `f`, `Esc`, or switching to another app leaves time entry without saving, and the countdown continues exactly where it stopped. Time entry no longer opens while paused or after time runs out, so a stray `f` cannot interrupt the overdue reminder.

**More accurate time.** Small timing delays no longer add up over time: the countdown stays in step with the clock, and no time is lost while the window is covered or the computer is busy. Pausing and resuming neither adds nor loses time.

**Keys that respond reliably.** `f` now works right away, without first clicking the time, which also used to reset the timer. `p` and `f` also work with Caps Lock or a Chinese input method on, and digits can now be typed with a Chinese input method on. Holding `p` no longer pauses and resumes over and over, and shortcuts such as Cmd+P no longer pause the countdown by accident.

**Smaller fixes**

- The overdue blinking stays in step with the numbers: each new number appears lit.
- On Windows, the unneeded Maximize and Minimize options are gone: double-clicking the window no longer maximizes it, and the right-click window menu no longer offers them.

**Upgrading.** The start time is now saved differently, so a custom start time goes back to 25:00 on the first launch after upgrading; set it again with `f`.

**Known issues.** On Linux the window opens at the wrong size, does not stay on top, and shows in the taskbar and `Alt`+`Tab`; the overdue blinking can be irregular.

## Under the hood

0.2.0 is a rewrite. In 0.1.1 the timer's behavior lived inside the page's event handlers: separate flags for paused, blinking, whether the blinking text was showing, and time entry, plus a countdown timer and a blink timer, all kept in agreement by hand. Unit tests covered the helpers, but how the handlers combined could be checked only by clicking through the app. Several of the fixes above trace back to that.

- **One model, one path.** Every timer rule now lives in `countdown-core`, a Rust crate with no browser or Tauri dependency. The page turns key presses, clicks and focus changes into inputs for the core, reads the clock and storage, and draws what comes back.
- **Specified, then tested.** The behavior was written down first in [docs/spec.md](https://github.com/jakrh/countdown/blob/v0.2.0/docs/spec.md), and the tests were written against it before the core was implemented. They cover every timer rule, run natively, and include property tests for the invariants. What only a real window can show (keys in each platform's WebView, focus, the window itself) is checked by hand on each platform. The reasoning is in [docs/design.md](https://github.com/jakrh/countdown/blob/v0.2.0/docs/design.md).
- **Time is derived, not counted.** A deadline replaces the per-second countdown, so a late timer cannot lose time, and the app wakes only when the displayed `MM:SS` changes.
- **Fewer dependencies.** The app no longer depends directly on Sycamore, serde or the opener plugin; the page is built directly with `web-sys`.

## 新功能與改善

**改時間不會再出錯**：不合理的數字（例如秒的十位打 7）當場就會被擋下，按 `Enter` 一定成功，不會再整筆默默失敗。四格數字直接覆寫，閃爍的游標用 `←` `→` 移動，`Backspace` 把游標所在的數字歸零。再按一次 `f`、按 `Esc`，或切換到其他程式，都會放棄修改、離開時間輸入，倒數會分秒不差地從停住的地方接著走。暫停中或超時後按 `f` 不再進入時間輸入，誤按不會打斷超時提醒。

**時間更準確**：細小的延遲不再隨時間累積，倒數始終和時鐘同步；視窗被遮住或電腦忙碌時也不會少算時間。暫停再繼續不會多算或少算時間。

**按鍵更可靠**：`f` 現在直接就能用，不必先點一下時間（以前那一下還會順便重設計時）。開著大寫鎖定或中文輸入法時，`p` 和 `f` 也能使用；開著中文輸入法也能輸入數字。長按 `p` 不再反覆暫停又繼續；Cmd+P 之類的快捷鍵也不會誤觸暫停。

**其他修正**

- 超時閃爍和數字變化同步，每個新數字出現時都是亮的。
- Windows 上拿掉了用不到的最大化與最小化：雙擊視窗不再把它放到最大，右鍵視窗選單也不再提供這兩項。

**升級注意**：開始時間的儲存方式改了，設定過的開始時間在升級後第一次啟動會回到 25:00，用 `f` 重新設定即可。

**已知問題**：Linux 上視窗開啟時大小不對、無法保持在上層，也會出現在工作列與 `Alt`+`Tab`；超時閃爍也可能不規律。
